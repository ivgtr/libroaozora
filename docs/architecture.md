# 本文APIとメタデータの設計

## 責務

`core` は型・CSV解析・ZIP展開・本文デコードを提供する。Workers は存在・権利確認、データの取得・保存・配信を担当し、表示用の構造化はクライアントが行う。セットアップと同期の実行方法は [README](../README.md) を参照。

## 本文の取得とキャッシュ

- リクエストごとに一つのメタデータ世代から作品の存在・著作権・配布URLを確認し、当該版のKV、R2、配布URLの順で取得する。著作権存続作品の本文は提供しない。
- 配布元へはサービスのUser-Agentを明示する。本文はアクセス時に取得し、メタデータ同期で全作品をダウンロードしない。
- ZIPの受信・展開サイズ、取得期限、同時処理数を制限する。通信失敗と内容破損を区別し、通信失敗だけで保存済みZIPを削除しない。
- 正常本文を得た後のR2・KV保存は独立して試行する。保存失敗だけで取得済みの正常本文を失わせない。
- 同一実行環境内で、作品と版が同じ進行中の処理を共有する。失敗直後の再取得を抑制し、429の有効な `Retry-After` を尊重する。分散ロックによる全環境横断の重複排除は行わない。

## 版と世代

| 識別子 | 意味 |
| --- | --- |
| `sourceRevision` | 配布URL・本文更新日・修正回数から生成する版識別子 |
| `contentId` | デコード形式の版と実本文のハッシュによる識別子 |
| `metadataGeneration` | 作品・人物・同期情報をまとめたスナップショットの世代 |

本文更新日などの欠損を現在日時で補わない。修正回数は非負整数・`-1`・欠損を区別し、不正な入力は同期時に拒否する。

本文は版別のKV・R2キーに保存する。同じ版へのR2書込みには条件付き操作を使い、既存の正常なデータを保護する。版と本文の整合性を確認できない応答は `unverified` とし、実際に返す本文の識別子を伝える。

## メタデータの公開と復旧

公式CSVの構造・必須項目・参照整合性を検証してから、R2スナップショットの保存・読戻し、同世代KV保存、`metadata/current.json` の切替を行う。KV保存はベストエフォートとし、読取りは同世代のR2へフォールバックする。KVの保存期間はメタデータが3日、本文が30日。

公開処理はデフォルトブランチの一つのGitHub Actions workflowに限定し、手動・定期実行を直列化する。途中失敗で正常な公開先を失わせず、再実行時の世代逆転を防ぐ。

初回移行では、正常な旧形式の `metadata/all.json` を直前世代として保持する。`metadata/migrated.json` は初回current公開より前に保存する一方向の移行マーカーであり、削除して旧形式へ戻さない。currentとマーカーがともに存在しないと確認できた場合だけ、readerは旧形式を読む。

移行後の障害では、正常なpointerが参照する現世代・直前世代だけを復旧候補にする。参照先が不明な状態でバケットを走査して世代を選ばない。復旧時はwriterを停止し、対象スナップショットの内容・digest・権利情報を確認したうえでpointerを復旧する。マーカーをlifecycle削除の対象にせず、readerの版互換性を維持する。

## 応答の検証状態

`delivery` はメタデータの世代・状態、本文の版・識別子、検証状態を返す。

- `current`: 現メタデータの版と正常本文の一致を確認できた状態。
- `stale`: 許可された正常な旧本文を提供する状態。
- `unverified`: 現行版との一致を確認できない状態。

検証日時は配信のたびに新しくしない。旧メタデータ・旧本文・通信失敗を最新版確認として扱わない。`health` が正常でも鮮度を保証せず、`metadataState` と同期情報を確認する。

一時障害では、権利と存在を確認できる範囲の正常な旧本文を利用できる。不存在・権利停止・明示的な提供停止・内容不正は旧本文で隠さない。旧版候補を全件探索せず、現・直前メタデータと互換キャッシュに限定する。

## 公開時の確認

対象環境の設定と認証を確認し、対応readerの公開、手動メタデータ同期、応答の世代と本文の整合性、日次同期、クライアントの訂正反映を確認する。コードのマージ、デプロイの成功、本文取得の成功、同期・訂正反映の完了はそれぞれ別に判定する。
