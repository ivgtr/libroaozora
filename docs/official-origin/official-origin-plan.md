## 1. 目的と合意済みの方針

GitHubミラーを必須とする取得経路をやめ、青空文庫の公式配布ファイルを取得する。
本文はAPIへのアクセスが発生したときだけ取得・保存し、全作品の事前取得は行わない。
メタデータ一覧は作品検索・著作権チェック・本文URL解決に必要なため、本文とは別に同期する。

```text
本文APIへのリクエスト
  → メタデータで存在・著作権・本文URLを確認
  → KVに有効な本文があれば返す
  → R2に有効なZIPがあれば展開して返す・KVへ保存
  → なければ公式から取得・展開
      → R2にZIP、KVに本文を保存して返す
```

- KV本文TTLは現行の30日を基本とする。
- R2の保存ZIPには期限を設けず、KV期限切れ後も再利用する。
- 本文を取得・展開できた場合は、キャッシュ保存失敗でレスポンスを失敗させない。
- 選定作品IDを障害回避のために差し替えない。
- 初回取得時に公式が利用できなければ、未保存作品を返せない制約は残る。
- 公式の訂正はメタデータで検知し、次のアクセスで本文を取得し直す。
- 同期ジョブは本文をダウンロードしない。
- 翌日1作品の先読みを維持する。今日の閲覧成功後に行い、失敗で画面を止めたり即時再試行したりしない。
- 一時的な公式取得障害では正常な旧版を提供する。提供停止を示す情報を検知した場合は旧版を返さない。
- 本文は版別、メタデータは単一世代のスナップショットとして保存する。
- 最終段階でブラウザ再検証・CDN・読書位置まで含む訂正反映に対応する。読書中は本文を差し替えない。

「アクセス」は本文APIへのリクエストを指し、利用に伴う翌日1作品の先読みを含む。
全作品を巡回・保存する処理は作らない。

## 3. 作業順序

### A. 公式への切り替え

1. `packages/workers/src/services/content.ts` のGitHub URL変換・ミラーフォールバックを削除し、
   メタデータの `sourceUrls.text` へ直接アクセスする。
2. `packages/workers/scripts/sync-metadata.ts` のCSV取得先を次へ変更する。
   `https://www.aozora.gr.jp/index_pages/list_person_all_extended_utf8.zip`
3. ZIP展開・Shift_JIS変換、作品の存在・著作権チェック、API応答形式を維持する。
4. 取得タイムアウトを維持する。ステータス・タイムアウト・展開失敗をログで区別する。
5. ミラー向けのテストを公式取得のテストへ更新する。

この段階は取得元の変更として単独で検証・レビュー可能にする。

### B. キャッシュの耐障害性と重複取得の抑制

1. KV読み出し失敗時はR2へ、R2読み出し失敗時は公式へ進む。
2. R2/KV書き込み失敗はログへ残し、取得済みの正常本文を返す。
3. R2読出しの通信失敗とZIP内容の破損を分離する。
   読出しの一時的な失敗だけで保存済みZIPを削除しない。
4. 同一実行環境内では、同じ作品・同じ更新版への進行中の取得処理を共有する。
   成功・失敗のどちらでも管理エントリを解放する。
5. 公式取得は1リクエストにつき1回とし、一時障害後には短い待機期間を設ける。
   429の有効なRetry-Afterを尊重する。待機中も正常キャッシュは利用する。
   管理Mapには期限と件数上限を設け、Responseストリーム自体を共有しない。
6. 分散ロックや全作品保存用の新基盤は初期実装に含めない。
7. 47927・789についてKV/R2ミス時、ヒット時、異なる作品の同時処理時のCPU・メモリ・応答時間を測定する。
   メタデータ解析とZIP展開を含め、本番契約の実行制限内で動くことを確認する。
8. ZIP受信・展開サイズ、同時処理数、本文取得全体のタイムアウトを測定に基づいて設定する。

初期はR2/KVの書込み結果をawaitし、各保存の失敗を独立して処理する。
応答遅延が問題と測定された場合にバックグラウンド保存を検討する。未awaitのPromiseを放置しない。
保存障害の継続時に先読みを停止できる設定を用意する。

### C. メタデータ同期と本文更新の識別

1. 公式CSVの本文更新日・修正回数・本文URLを内部の更新識別に利用する。
   現在の `Work.updatedAt` は作品全体の「最終更新日」であり、本文専用ではない。
2. 完全な本文URL・本文更新日・修正回数・識別方式のバージョンから `sourceRevision` を作る。
   KVは `content:v2:{workId}:{sourceRevision}`、R2は `content/v2/{workId}/{sourceRevision}.zip` とする。
   取得元・取得日時・版・ZIP/本文ハッシュを対応付け、構造化処理の形式バージョンも本文ハッシュとは分ける。
   欠損情報を現在日時で補わない。遅れて終わった旧版取得が新版を上書きしないようにする。
   同じ識別子で異なる内容を観測した場合のログ・条件付き保存も実装時に検証する。
3. 変更された本文は、次のAPIアクセスで再取得する。全件再取得はしない。
4. 更新情報のない既存キャッシュは、アクセス時に公式から再取得して新形式へ移行する。
   一括削除は行わない。移行前の正常ZIPは一時障害時の旧版候補として利用できるが、最新版とは認定しない。
5. メタデータの定期同期をまず1日1回とする。現行workflowのscheduleはコメントアウトされている。
6. ダウンロード・展開・CSV検証完了後に公開用メタデータを更新する。
   更新失敗時に直前の正常データを保持し、同期の重複実行を防ぐ。
7. 作品・著者・同期日時を一つのJSONにまとめ、`metadata/snapshots/{generation}.json` としてR2へ保存する。
   保存完了後、現世代・直前世代を示すR2の `metadata/current.json` を切り替える。
   KVは `metadata:{generation}` として同じJSONを保持し、KV失敗時は同世代のR2から読む。
   currentの更新者を同期ジョブに限定し、手動実行を含む同期経路を直列化する。
8. 現世代が読めず旧世代を使った場合は明示的に記録する。作品・著者を別世代から合成しない。
   currentの短時間キャッシュにより許容する反映遅延も明記する。

#### 旧版提供とエラー分類

- 現在のメタデータで提供可能な作品に限り、通信失敗・タイムアウト・429・5xxでは正常な旧版を返す。
- 公式403/404/410、メタデータ上の削除・著作権制限・本文URL削除、新ZIPの破損では旧版へフォールバックしない。
- 保存済みZIPは、読出しの通信例外だけでは削除しない。
- 旧版候補は直前世代が示す版・移行前キー等の少数の既知候補に限定し、見つからなければ取得エラーとする。
- 旧版を新版キーへ保存せず、実際の本文識別子と旧版利用状態を応答に含める。
- 作品不存在の404、著作権制限の403、配布元の取得障害、想定外の500を安定したcodeで区別する。
  中継が例外メッセージ文字列を解析する実装にはしない。

本文識別子・メタデータ世代・検証状態を互換性のある追加フィールドとして応答に含め、中継も伝達する。
メタデータと本文の並列取得が世代をまたいだ場合を検出し、正常な同一世代へ揃える経路を実装・検証する。
具体的なフィールド名と、必要な場合の同一世代再取得/応答統合は実装設計で決める。

### D. ブラウザ・CDN・読書位置への更新反映

1. IndexedDBの `lastAccessedAt` は削除判断用に維持し、最終確認日時 `checkedAt` と本文識別子を追加する。
2. 作品を開くとき、オンラインかつ再検証間隔を超えていれば再検証する。全件巡回はしない。
   通信失敗・旧版提供を最新版の確認成功として扱わない。旧エントリは未検証として移行する。
3. オフライン・一時障害時は保存済み本文を利用する。利用停止等を検知した応答とは区別する。
4. 読書開始前に更新できれば新版を使い、読書中の本文は差し替えない。
5. 再開位置に本文識別子を持たせ、版が変わった場合は短い通知とともに先頭へ戻す。
   お気に入り・読了履歴・累積記録は維持する。文脈による位置復元は対象外とする。
6. 正常応答のCDNキャッシュは1時間を基本とし、現行24時間のstale-while-revalidateを外す。
   旧版フォールバック応答は長期共有キャッシュせず、ブラウザへ状態を伝える。
7. 同期・currentキャッシュ・CDN・ブラウザを通した反映遅延を検証する。
   オフライン・開かない作品・表示し続けた画面への即時反映は保証しない。

### E. ログと運用確認（各段階に含める）

- 本文: workId、処理段階、取得先、上流status、元例外、保存失敗。
- 同期: 開始・成功・失敗日時、作品数・人物数、公開した世代。
- APIエラー本文に内部例外を公開しない。
- ログ・メトリクスから公式への取得回数と保存失敗の継続を確認できるようにする。
- 設定する上限や警告閾値は測定値・契約枠から決め、架空の公式許容レートを設定根拠にしない。

### 初期設定と実装時に調整する値

| 設定 | 初期値・方針 |
| --- | --- |
| KV本文TTL | 30日 |
| R2現行ZIP | 期限なし |
| メタデータ同期 | 1日1回 |
| ブラウザ再検証間隔 | 24時間 |
| currentの実行環境内キャッシュ | 60秒 |
| 一時障害後の待機 | 60秒を基本とし、有効なRetry-Afterを尊重 |
| 正常応答のCDNキャッシュ | 1時間、24時間のstale-while-revalidateは削除 |
| 公式取得 | 1リクエストにつき1回。現行10秒タイムアウトを起点に全体の期限を調整 |
| ZIP/展開サイズ・同時処理数・Map件数 | 代表作品と本番プランの測定後に設定 |

時間値は初期設定として採用し、測定に基づく調整を可能にする。公式の許容アクセス頻度や厳密な更新SLAを意味しない。
